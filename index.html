Undo/Redo Editor

A stack is a pile: the last item placed on top is the first one taken off. Below are the real-world places that depend on that rule, why a stack is the right structure, and a working editor whose undo and redo run on two stacks.

Why stacks are necessary

The newest thing matters first. Many problems nest: finish the innermost task before the outer one, or reverse the latest step before earlier ones. Reversal for free. Pushing items and popping them returns them in reverse order. Speed. push, pop and peek all take constant time because only the top is touched. Safety by restriction. Access is allowed at one end only, so the structure cannot be used out of order. A queue would give back the oldest step, which is the wrong one to undo.

The build: undo/redo with two stacks

Every edit pushes the previous document onto the undo stack. Undo pops it and pushes the current state onto the redo stack. A new edit empties the redo stack, as in real editors.
